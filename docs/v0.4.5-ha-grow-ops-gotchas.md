## A. 仍需手动 → 自动化/修复 backlog（朝零手动运维）

1. **seed 发布是手动的**。grow 后 `cluster seeds publish` 才能让 agents 自动发现新 broker（auto-discovery
   本身是自动的，但发布这一步要人做）。**自动化**：membership 变化（join/retire 提交）后，leader 自动从
   各 broker 的 `broker.yaml` public_host/domain 派生 client-dialable 端点、自动 bump seed_generation
   发布。没这步 → 关老 broker 时 agents 切不过去。

2. **proxy status / 订阅按订阅 host 渲染所有 exit**。N=2 后 `tether proxy status` 把 pc732-homed 的 exit
   也标成 `linziyang.top:1400x`（订阅 host），实际 egress 在 `weiland.top:1400x`（端口监听铁证）。
   **风险**：订阅下发给 Clash 的 server host 若也错，pc732-homed 那几条会连不上。**修**：每个 exit 用它
   自己 home broker 的 public_host 渲染，不用订阅 host。（订阅 host 本身为什么固定到 racknerd 也要查。）
   **附带验证**：rebalance 后 broker 端订阅内容是对的（`curl weiland.top/sub/<token>` 每个出口指向其真实
   home：pc732-homed→weiland.top:1400x、racknerd-homed→linziyang.top:1400x）。**但客户端(Clash Verge)的
   proxy-provider 缓存是旧的 → rehome 的节点超时,要手动在 UI 刷 provider**(mihomo 控制器在 Clash Verge 里
   是命名管道、TCP 关,没法外部程序化刷)。零手动运维点：缩短 provider interval / rebalance 后主动让订阅带
   staleness 信号 / 客户端缩短刷新周期。

3. **首次 standalone→clustered 的 NATS mesh `reconcile nats --all` 渲染不出来**。`BuildMergedConf` 从
   现有 conf 的 `cluster{}` 块 harvest mTLS 证书路径；standalone conf 没这块 → 报
   `live conf has no cluster{} block to harvest routes mTLS from`。只能用
   `reconcile nats --manual --secrets-dir --peer <对方>`（显式给 mTLS）。**修**：auto-reconcile 在 conf
   无 cluster 块时 fallback 到 `secrets-dir` 取 mTLS，让 `--all` 能做首次 grow。

4. **former-N1 节点的 JS store reset 是手动 + 有数据损失**。standalone JS 不迁进 clustered meta，重启
   clustered 会孤儿化旧流；runbook 要 `rm -rf /var/lib/tether/jetstream`（丢 history/audit）。
   **自动化**：grow 时自动检测 + 自动 reset（或自动 `nats stream backup`→reset→`restore` 保数据）。
   本次用 `mv jetstream → jetstream.grow-bak.<ts>`（可回滚）代替 rm。

5. **`cluster init` 没有机器可逃生的 confirm**。`confirmTypedNodeID(..., allowMachineEscape=false)` 强制
   TTY 输入 node_id；自动化要 Python pty 喂。（`resnapshot` 有 `--confirm-node-id`+env 逃生，init 没有。）
   **修**：给 init 加同样的 machine-escape confirm（或 `--yes-i-understand` 之类）。

6. **`tether.lock` 被 root `cluster init` 建成 root-owned** → 之后 `sudo -u tether` 跑 offline op
   （resnapshot）开锁 permission denied。**修**：init/install 确保 data_dir + lock 归 broker 用户
   （类似 audit C 的 /etc/tether chown）。本次手动 `chown tether tether.lock` 解锁。

7. **catch-up deadline（opCatchupTimeout=2min）对慢 InstallSnapshot 太短** → join STALLED、要手动
   `cluster ops confirm` 重试（大 DB 经网络装快照 >2min）。**修**：deadline 按快照大小/进度自适应，或
   stall 后自动重试若 joiner 仍在追。

8. **catch-up 探测要 joiner NATS 可达**（`clusterCaughtUp` 经 `SubjClusterCursor` scatter-gather）→ NATS
   mesh 必须先渲染好 joiner 才算追上 → 与"先 join 再 reconcile nats"的 runbook 顺序成鸡生蛋。**自动化**：
   grow 编排里 AddNonvoter 后自动渲染 mesh，再判 catch-up，再 AddVoter。

9. **ctl 没有持久 roster 缓存**（**真机证实 2026-06-28 阶段4**）→ 配的 broker（pc732）一关,本机 ctl 连不上
   `nats: no servers available for connection`、**不会自动切 racknerd**（agents 有 roster_cache 会切）。
   用户预期"cli 理应自己找出路",未达成。**修**：ctl 也持久化发现的 roster（从 cluster seeds）+ 连接失败
   时自动遍历 fallback 端点;或 broker_url 支持多端点列表。**这是用户明确要的功能缺口,优先级高。**

11. **运维命脉/观测通道不能依赖被测死的节点**（**真机证实 2026-06-28 阶段4**）。本机到 racknerd 的 wss
    (`--nats-url linziyang.top:443`)和 SSH 都经 Clash:`linziyang.top` 解析成 fake-ip `198.18.x`、非 Clash
    DIRECT → 走代理链,而链路依赖 pc732 → **杀 pc732 后,我到幸存者 racknerd 的 wss + SSH 同时断**
    (`tls error: EOF` / `Connection closed by 198.18.x`),保护模式期间看不到幸存者(只能靠重启 pc732 后
    事后取证 journal 确认它没崩)。**真 failover 测试前必须先建一条到幸存者的 pc732-独立通道**:SSH key 直连
    racknerd 真实 IP(`23.95.48.156`,需在 Clash 里对该 IP 走 DIRECT 或确认本就 DIRECT)。**零手动运维点**:
    cluster seeds 应让客户端缓存"按真实 IP 直连"的 fallback,使运维/观测不被单点 DNS/代理链卡死。

10. **N=1-clustered JS 陷阱**（已改 actionable 错误但仍要手动）。cluster 模式 + clustered-N=1 conf →
    JS meta 形不成 → broker 退 70 崩溃循环。v0.4.5 报错已指明 remedy，但仍要人手 `reconcile nats
    --to-standalone`。**自动化**：N=1 自动收敛到 standalone（受 R3 "不静默 de-cluster" 约束,需谨慎设计）。

## B. 终极自动化目标
把整条 grow 序列（leader resnapshot 若需 → joiner init → join → 渲染 mesh → reset JS → 发布 seed →
rebalance proxy）收进**一条 `tether cluster add <new-broker>` 编排命令 / 向导**，全自动幂等可恢复，
而不是本次的 ~15 步手动 + detached 脚本 + pty 喂 confirm + 多次重试。

## C. 运维环境踩坑（非代码,记给接手者）
- `tether exec` 经 broker 偶发 `wss tls error: EOF` 瞬断 → 重试。
- 直连 SSH 经 Clash fake-ip(198.18.x) 偶发 `Connection closed` → 重试或改 `tether exec`。
- 停 broker/nats 的 op 会断 `tether exec` 通道（它经 broker→nats）→ 用 `systemd-run --collect` detached
  （launch 经 tether exec 会先返回再停服务）。
- pc732 SSH = `ssh pc732`（config 里有）;racknerd = `ssh root@linziyang.top`。两台 broker bin
  `/usr/local/bin/tether`,经 host `curl` GitHub release 部署(JS down 时 `tether push` tier-B 用不了)。
- classifier 会拦生产破坏性命令(rm -rf、scp 脚本、systemd-run 跑含破坏内容的脚本)→ 用 mv 代替 rm、
  或让用户授权。
