## Findings

### F1 - High: stale-socket reclaim unlinks a live broker socket

`internal/adminsock/server.go:76-87` removes any existing socket inode before
calling `net.Listen`. That is safe for a truly stale dirent, but unsafe for an
active broker. On Unix, unlinking a live listening socket path does not close
the old listener; it only removes its pathname. A second broker can therefore
silently steal `/var/run/tether/admin.sock`, leaving the first broker running
but unreachable via the documented admin path.

Reviewer test added:

```text
go test ./test/p9 -run TestReviewAdminSocketDoesNotUnlinkActiveSocket -count=1 -v

second admin socket unexpectedly started on an active socket path; it must not unlink a live broker socket
```

Recommendation:

Before unlinking a socket path, try a short Unix dial. If it succeeds, return a
clear `adminsock: active socket already exists` error. Only unlink when connect
fails with a stale/unreachable socket. Also consider making `acceptLoop` hold a
local listener variable; during testing I hit a `Close`/`acceptLoop` nil-listener
race when closing immediately after `Start`.

### F2 - High: `tether serve` does not enable the admin socket by default

`cmd/tether/admin.go:16` defaults the client to `/var/run/tether/admin.sock`,
but `cmd/tether/serve.go:120-121` defaults `--admin-socket` to empty, which
disables the server endpoint. With the current defaults, `tether serve` starts
without the P9 admin surface, while `tether admin sessions` tries to connect to
a socket that was never created.

Reviewer test added:

```text
go test ./cmd/tether -run TestReviewServeAdminSocketDefaultMatchesAdminClient -count=1 -v

serve --admin-socket default = "", want "/var/run/tether/admin.sock"
```

Recommendation:

Use `defaultAdminSocket` as the `serve --admin-socket` default, or make
`broker.yaml` generated by the production path always include
`broker.admin.socket: /var/run/tether/admin.sock`. The default client and
server behavior should match.

### F3 - Medium: existing admin socket parent directories are not hardened

`adminsock.Server.Start` calls `os.MkdirAll(parent, 0700)`, but `MkdirAll` does
not change permissions when the parent already exists. If `/var/run/tether` is
created by packaging, tmpfiles, or an operator with mode `0755`, P9's "parent
directory 0700" invariant is not restored by the broker.

Reviewer test added:

```text
go test ./test/p9 -run TestReviewAdminSocketChmodsExistingParent -count=1 -v

admin socket parent mode: got 755 want 0700 even when parent pre-exists
```

Recommendation:

After `MkdirAll`, call `os.Chmod(parent, 0700)` and fail if it cannot be
hardened. Keep the socket file `0600`.

### F4 - Medium: broker.yaml production fields are parsed but not wired

The architecture A.3 skeleton uses `broker.domain` and `frp.port_range`.
`internal/serveconf/serveconf.go:23-45` parses both `Domain` and `PortRange`,
but `cmd/tether/serve.go:44-68` never applies them to `broker.Config`.

Impact:

- a config containing only `broker.domain: tether.example.com` still leaves
  `PublicHost` at the CLI default `localhost`, so `tether expose` prints
  localhost URLs in a production config unless the operator knows to add the
  extra non-skeleton `public_host` key;
- `frp.port_range` is ignored, so a broker.yaml/firewall configured for a
  custom exposed range still allocates from the hard-coded default range.

Recommendation:

Default `PublicHost` from `broker.domain` when `broker.public_host` is absent,
and parse `frp.port_range` into `broker.Config.PortBandLow/PortBandHigh`.
Add config precedence tests covering `flag > yaml > default` for these fields.

## Maintainer Response (round 1)

Date: 2026-05-09

All four findings accepted; nothing to push back on. Each was a real
production-surface defect.

### F1 — accepted, fixed

`adminsock.Server.Start` now probes the path with `net.DialTimeout`
before considering an unlink. Connectable → return `adminsock: active
socket already exists at <path>`; not connectable → safe to reclaim.
Also fixed the `Close`/`acceptLoop` nil-listener race the reviewer
called out: `acceptLoop` now takes the listener as a parameter and
owns its own reference, so `Close` setting `s.listener = nil` can no
longer race with `Accept`.

Reviewer's `TestReviewAdminSocketDoesNotUnlinkActiveSocket` now passes.

### F2 — accepted, fixed

`cmd/tether/serve.go` `--admin-socket` default is now
`defaultAdminSocket` (= `/var/run/tether/admin.sock`), matching
`cmd/tether/admin.go`. broker.Config.AdminSocketPath still treats
empty as "disabled", so the in-process tests that don't exercise
admin (test/p4..p8) remain unaffected — only the CLI-driven `tether
serve` flow gets the production-path default.

Reviewer's `TestReviewServeAdminSocketDefaultMatchesAdminClient` now
passes.

### F3 — accepted, fixed

`adminsock.Server.Start` now defensively `os.Chmod(parent, 0o700)`
after MkdirAll. Failure is fatal: continuing would leave the socket
exposed to any local user, which violates the architecture P9
invariant. The cost is a re-chmod every start; the gain is that an
operator-pre-created `/var/run/tether` at 0o755 (or a tmpfiles.d
default) cannot silently weaken the security boundary.

Reviewer's `TestReviewAdminSocketChmodsExistingParent` now passes.

### F4 — accepted, fixed

`cmd/tether/serve.go` now wires both fields:

- `pickPublicHost` extends the standard precedence chain to:
  explicit `--public-host` > yaml `broker.public_host` > yaml
  `broker.domain` > cobra default. So a minimal broker.yaml with
  only `domain: tether.example.com` Just Works for `tether expose`
  URLs without requiring a duplicate `public_host` key.
- `parsePortBand` parses `frp.port_range "low-high"` into
  `broker.Config.PortBandLow/High`. Empty input keeps the
  14000-14999 default; bad input is fatal at `tether serve` start
  rather than silently landing on the default (an operator who
  configured a custom firewall range would otherwise discover the
  mismatch only via failed `expose` calls).

Added precedence + parser tests in
`cmd/tether/serve_config_test.go`:

- `TestPickPublicHostPrecedence` — 4 sub-cases covering the chain.
- `TestParsePortBand` — 10 sub-cases covering empty / valid /
  inverted / non-numeric / out-of-range.
- `TestPickFlagOrYamlPrecedence` — generic flag>yaml>default.
