# Independent findings and disposition

## S1 — Major — rejected/expired cache can manufacture durable route identity (fixed; independently reverified)

Initial candidate locations: internal/agent/roster.go:73 assigned persisted rc.Roster before verification; rememberConnectedBroker around :605-615 treated cachedRoster as accepted evidence without an expiry check; :595-600 retained this newly inferred identity on later N-1 replies.

Trigger: a normal expired persisted roster, or one that verified at boot and expired during this process, matches the current URL host. A fresh valid signed N-1 response then replaces the roster with the actual single broker under another alias. Because remember runs before adoptRoster, the stale roster supplies an old NodeID; that ID survives replacement of the roster. rebuildOnBrokerSilence considers the actual sole broker to be a different survivor and really cancels the session.

Independent test: TestRosterRouteIdentityRejectsInvalidBootCache (internal/agent/roster_route_identity_test.go), actual state-store serialization/load plus real NATS refresh, valid signatures, injected clock, and actual session cancellation assertion. Five arms (expired at boot, expires after boot, bad signature, foreign account, validly re-signed future schema) all failed with the original candidate: round2-roster-cache-before.log, package 0.498s under -race. The ordinary expiry arms require no malicious filesystem write. Corrupted/foreign cache arms separately test rejection boundaries and are not claimed as a remote exploit.

The underlying pre-verification cachedRoster assignment and prior silence use existed before this increment; the new persistent route identity carries that invalid evidence across a subsequently accepted valid roster. This is an incomplete fix of the stated single-broker/roster trust contract, not a claim that every ingredient was newly introduced.

Root fix: only assign the runtime cachedRoster after VerifyAt succeeds at boot; retain durable account pin and generation high-water marks. Use the shared rosterCurrentAt at identity derivation and silence decision time. Independent source check confirms no change to durable pin/anti-rollback semantics. Five negative arms plus the previous identity/real sole-survivor tests passed -race -count=3 (round2-roster-cache-after.log, 5.920s). Added TestRosterRouteIdentityPreservesVerifiedIngress checks two positive cases: a fresh cache can supply an N-1 host identity; an identity proved while fresh persists on the same live route after the roster expires and a fresh signed roster removes it. Both controls plus all five negatives passed three race rounds (round2-roster-cache-controls.log, 2.752s).

## S2 — Major — ambiguous N-1 hostname is recorded as a confirmed broker ID (fixed; independently reverified)

Pre-fix location: internal/agent/roster.go:610-611, rememberConnectedBroker. The fallback assigns the first matching NodeID and never asks whether another distinct NodeID matches the same hostname. Roster sorting makes this a deterministic preference for the first ID, not a unique identity proof. A NATS route hostname can be shared by two members with different ports; client URL port and route port also have different roles, so merely comparing ports cannot repair the inference.

Independent TestRosterRouteIdentityRejectsAmbiguousHost establishes a signed two-member roster with a shared route hostname and distinct ports, accepts an N-1 reply on a real NATS connection, then adopts a fresh signed roster that removes the first member and updates the remaining member's route hostname. The remaining broker's public host stays unchanged. The guessed removed ID survives, so silence actually cancels the current sole broker. -race failed in 0.086s; round2-roster-ambiguous-before.log. This test models membership replies and does not claim a true raft membership change or distinct physical deployments.

Root accepted and implemented uniqueRosterNodeAtHost: encountering two distinct matching NodeIDs returns unknown instead of persisting the first. Explicit ConnectedBrokerID and already confirmed same-route identity bypass the fallback. Independent final -race -count=3 run includes the original ambiguous-host negative unchanged in behavior, an explicit-ID positive arm, the unique verified-cache/retired survivor controls and all S1 negatives. All passed: round2-system-identity-final.log, 6.755s. The instant silence predicate can still conservatively exclude all matching host aliases; it does not persist its temporary selected ID. This is a routing-availability issue; the discovery hint confers no membership authority.
