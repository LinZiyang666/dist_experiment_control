## Confirmed BLOCKERs

### B1 — Cluster `proxy off` does no data-plane teardown; kill switch is fail-open
*(consolidates C5-FCD-1 + C5-DP-01 — same defect via fail-closed-degraded and data-plane lenses)*

- **Where:** `internal/broker/proxy_cluster_wire.go:70-101` (`handleProxySetCluster`); the authoritative single-mode kill switch it bypasses is `internal/broker/proxy.go:135-200` (`disableProxy`).
- **Scenario:** In cluster mode `handleProxySet` (`proxy.go:63-66`) routes into `handleProxySetCluster` and returns *before* reaching `disableProxy`. For `enabled==false` the cluster handler ONLY `proposeOrForward(VerbProxySetEnabled, …)` (commits `proxy_enabled=0` + keyset-epoch bump) + audit, then replies OK. It never: frees the `__proxy__` `port_allocations` row, calls `tunnelSrv.CloseSession(sid)` to close the bound public listener, or pushes an `Enabled:false` directive to the agent. No path compensates:
  - the reaper's `activeProxySessions` (`proxy_reconcile.go:46`) filters `WHERE proxy_enabled=1`, so the just-disabled session is dropped from reconciliation entirely;
  - `repairProxy` is a hard no-op in cluster mode (`proxy.go:687-689`), disabling the single-mode heartbeat OFF-repair (`proxy.go:735-743`);
  - `reconcileTunnelSessions` only closes on row-missing/identity/home/epoch mismatch — none fire because the `__proxy__` row stays ALLOCATED with unchanged identity/home/home-epoch;
  - the agent's `applyProxyDirective` tears down only on an explicit `!d.Enabled` push, a token-bearing full re-establish, or the 15-min NATS-partition fail-closed timer — none of which a cluster `proxy off` produces; a nil register directive is an explicit no-op (`agent/proxy.go:115-117`).
- **Net effect:** After `proxy off` in a healthy quorum the agent's embedded SS server keeps serving (`proxyBound()` stays true), the reverse tunnel + bound public port stay open, and the `__proxy__` row stays ALLOCATED (leaked on every off/on cycle). Only `proxy_ready` is cleared (heartbeat switch-gate `broker.go:1179-1184`), so `/sub` renders empty for *new* discovery — but any client holding the previously-fetched Clash config (home public host + port + PSK) keeps egressing **indefinitely**. `tunnelTokenLookup` only denies a *re-REGISTER*, so an established session never trips it. This is a fail-open regression of the property `disableProxy` documents at `proxy.go:139-141`. The plan §2 (`c5-plan.md:31`) explicitly specified "Reuse `OpPortFree` (proxy-off/sub teardown)" — it was not wired.
- **Fix direction:** On a cluster OFF, after committing `VerbProxySetEnabled`, the leader must drive the full teardown via Raft + NATS: (1) commit `OpPortFree` for each `__proxy__` row of the session (the verb is already in the plan and the forward set); (2) `tunnelSrv.CloseSession(sid)` on every broker that holds the listener — since the home may be remote, broadcast a teardown nudge or have each broker close its own home-owned proxy listeners on observing `proxy_enabled=0`; (3) push an `Enabled:false` directive to each online NID so the agent stops its SS server. Simplest correct shape: make the reaper OFF-aware — have `activeProxySessions` (or a sibling pass) also surface sessions with `proxy_enabled=0` that still have ALLOCATED `__proxy__` rows / live `proxy_ready`, and have the reaper drive `OpPortFree` + `Enabled:false` push + local `CloseProxy` to convergence (idle-zero-writes once torn down). Mirror the synchronous-listener-close + port-free + disable-push trio of `disableProxy`.

### B2 — `PlanAllocateProxy` reads the free port on RODB *outside* `applyMu`; UNIQUE trip at Apply → FSM fail-stop panic cluster-wide
*(consolidates C5-RBE-1 + C5-DP-02 — same defect via routing-byte-equiv and data-plane lenses)*

- **Where:** `internal/broker/proxy_reconcile.go:104-112` (`allocateAndPushProxy`); plan helper `internal/port/plan.go:198-233` (`PlanAllocateProxy`); contract it violates `port/plan.go:88-92` + `clustermeta.go` `genericExecApplier`.
- **Scenario:** `allocateAndPushProxy` bakes the allocation *before* the Raft write window:
  ```go
  alloc, cmd, err := port.PlanAllocateProxy(b.cfg.DB, sid, nid, home.NodeID, ...)   // :104
  b.cl.node.Propose(func(_ *sql.DB) (*cluster.Command, error) { return cmd, nil })  // :108 — ignores n.db
  ```
  In cluster mode `b.cfg.DB == cl.node.RODB()` (`broker.go:606`) — the read-only pool, **not** the single-writer FSM pool. `PlanAllocateProxy` runs `findFreePort` against that RODB snapshot and bakes a fixed `INSERT(port=P, state='ALLOCATED')`; the Propose closure discards the live `n.db` that `Node.Propose` hands it under `applyMu` (`node.go:380-385`). So the port choice is never serialized under `applyMu` — exactly what `PlanAllocate`'s own doc forbids ("MUST run under `Node.Propose` (applyMu) so two concurrent allocations cannot bake the same port"), and exactly why `PlanAllocate` added a desired-port precheck (`plan.go:124-141`). `PlanAllocateProxy` has neither. The proxy free-then-insert "fence" only clears the per-`(sid,nid,'__proxy__')` row; it does **not** cover the global `idx_port_alloc_unique_active` (UNIQUE(port) WHERE state='ALLOCATED', `0003_port_alloc_history.sql:44-46`).
- **Trigger:** Leader-gated reaper (`observability.go` observe ticker) runs `findFreePort` on RODB → port P; concurrently a ctl `expose` arrives → `proposeOrForward` → `Node.Propose` acquires `applyMu` → `PlanAllocate(n.db)` picks the same lowest-free P → commits + Applies `INSERT P` → releases. The reaper's Propose then Applies its pre-baked `INSERT P`, tripping the UNIQUE index. (RODB read-lag vs `n.db` widens the window even without a concurrent expose.) A proxy-enabled session that also runs exposes is the explicit C5 use case.
- **Net effect:** `OpProxyAllocate` → `genericExecApplier.ApplyTx` returns a **plain exec error**, NOT `errAppliedRejected` (`clustermeta.go:71-78`), so the FSM retry loop re-applies the same committed entry, fails deterministically every attempt, and panics (`fsm.go`). Fail-stops **every** replica that applies the entry, and re-panics on post-restart log replay = permanent brick. The guard note (`proxy_cluster_guard_test.go:28-30`) explicitly blesses reading `b.cfg.DB` here — encoding the bug as intent.
- **Fix direction:** Plan `PlanAllocateProxy` **inside** the Propose closure on the passed `db`, like `PlanAllocate`/`PlanReassignHome` (the correct pattern already exists one function down at `rehomeProxy` `proxy_reconcile.go:122-125`, and at `allocatePort` `clusterwrite.go:524-526`). Add the same two prechecks `PlanAllocate` has: per-`(sid,nid)` proxy-unique AND per-port global-unique, so a collision is detected pre-commit (caller no-ops/retries) instead of committing a poison entry. The raw token must then be leak-once-captured from inside the closure (mirroring `allocatePort`, as `c5-plan.md` D-SECRET requires).

## Confirmed MAJORs

### M1 — Reaper home-down trigger is `Eligible()`==phase-VOTER only; a crashed home broker is never detected, so crash-failover never fires *(C5-FCD-3)*
- **Where:** `internal/broker/proxy_reconcile.go:74-94` (`reconcileProxySession` / `proxyHomeHealthy`); `clusternodes/read.go:45` (`Eligible()`).
- **Scenario:** The reaper rehomes only when `!proxyHomeHealthy(home)` for `proxyRehomeDwell` ticks. `proxyHomeHealthy = home.Eligible() && home.CertFP != ''`, and `Eligible()` is purely `Phase=='VOTER'` — no reachability dimension. A raw broker **crash** never mutates `cluster_nodes.phase` (the only phase mutator is planned drain/retire via `membership_ops.go`); the §17 observe loop merely RAISES a `broker_down` alert, it does not demote the dead voter or clear `cert_fp`. So a killed home stays `phase='VOTER'` + non-empty `cert_fp` → `proxyHomeHealthy`==true → the dwell counter is reset every tick → the reaper **never** fires `OpPortReassignHome`. Meanwhile `liveProxyNodes` (`subhttp.go:189-206`) keeps JOINing the dead home (`cn.phase='VOTER' AND public_host!=''`) → `/sub` renders an exit pointing at the dead broker's public host. On reconnect the agent gets the SAME dead Home back (`proxy.go:478-503`, no epoch bump → agent `ApplyHome` guard no-ops). Recovery requires an operator `cluster retire`. This violates the C5 acceptance ("killing the proxy home broker ⇒ auto-switches WITHOUT proxy off/on") — the implemented trigger handles planned drains, not the crash scenario the acceptance names. Plan D-REAPER specified rehome on "SUSTAINED down" (a reachability signal, "distinct from the 1-window alert"); the implementation wrongly uses the *target-eligibility* predicate as the *trigger*.
- **Fix direction:** Decouple the rehome trigger from `Eligible()`. Drive it from an actual liveness/reachability signal of the home broker — e.g. the §17 per-peer reachability the `broker_down` alert already computes, or a last-contact staleness on the home — and keep the dwell hysteresis. Keep `Eligible()` (+ `cert_fp` + `public_host`) for *target selection* only (`pickProxyRehomeTarget`), not for the down-trigger. (See also M-DP07 nit: align the down/healthy predicate with the `/sub` render predicate.)

### M2 — Cluster `proxy_ready` derives from `ProxyBound` (SS-server-bound), not tunnel liveness; the per-heartbeat write resurrects readiness over a real tunnel-down → `/sub` vends dead-tunnel exits *(C5-DP-03)*
- **Where:** `internal/broker/broker.go:1173-1188` (cluster heartbeat handler); `internal/agent/proxy.go:83-91` (`proxyBound`); `subhttp.go:200`.
- **Scenario:** In cluster mode the heartbeat sets `proxy_ready = hp.ProxyBound && proxy_enabled` every tick. `hp.ProxyBound == (p.srv != nil)` — i.e. the embedded SS *server* is bound, regardless of whether the reverse tunnel to the home is connected. The agent still computes accurate tunnel-liveness on the up/down edge (`onTunnelSessionState → pubProxyReady`, the P13 "Defect B" fix) and `handleProxyReadyEvent` writes it — but the next heartbeat (within `HeartbeatInterval`, ~5s) re-sets `proxy_ready=1` from `ProxyBound`, overriding the unready. Result: on a pure tunnel drop (SS server still up, home alive), the node stays `proxy_ready=1` on every broker, `/sub` keeps vending it, and `proxy status --cluster` mislabels it `ready` (the `tunnel_down` reason keys on the resurrected `proxy_ready`, never the actual tunnel). Diverges from single mode, where `proxy_ready` tracks the real tunnel edge and the node stays OUT of `/sub`. (Note: the reaper does NOT rehome here — the home is alive — so the node is vended-but-broken until the tunnel auto-reconnects, not bounded by `proxyRehomeDwell`.)
- **Fix direction:** Don't let an unconditional per-heartbeat `ProxyBound` write override an agent-published tunnel-down. Either (a) have the agent's `ProxyBound` reflect tunnel liveness (only true when the proxy tunnel session is up, not merely `p.srv!=nil`), or (b) make the heartbeat write *advisory-only* — never raise `proxy_ready` from 0→1 from `ProxyBound`; let the agent's `proxy.ready` edge own the rising edge while the heartbeat ProxyBound==false can still clear it. Preserve the cross-broker convergence intent of D-PROXY-READY without dropping the tunnel-liveness dimension single mode had.

### M3 — No token re-mint / re-delivery in cluster mode; a lost token-bearing push (or lost agent `state.json`) strands the node "enabled but never gets a port" forever *(C5-DP-04)*
- **Where:** `internal/broker/proxy_reconcile.go:99-113` + `:160-165` (only token mint+push); `internal/broker/proxy.go:478-503` (token-less register branch); `internal/port/port.go:620-626` (`LookupProxyByNode` loads only `token_hash`); agent `proxy.go:187-196`.
- **Scenario:** The raw `__proxy__` token is delivered exactly ONCE — only `allocateAndPushProxy`, reached only when `LookupProxyByNode` returns no row, mints + pushes a token-bearing directive. Once the row exists, every later reaper push and the cluster register path are token-LESS (the row carries only `token_hash`). NATS core forwarded pushes are at-most-once. If that single token-bearing push is dropped (transient reconnect) or the agent loses `state.json`, the agent hits `applyProxyDirective` case `p.srv==nil` with no persisted footprint → logs "awaiting full directive" and no-ops **forever**: the cluster heartbeat never calls `repairProxy` (no-op in cluster mode), and the reaper never re-mints for an existing row. Single mode self-heals here (`proxyDirectiveForRegister` mints a FRESH `AllocateProxy` on a non-matching token hash, `proxy.go:535-543`); the cluster branch removed that net. The node stays ONLINE throughout (so the offline-revoke can never fire), and reconcile-on-register deliberately does not revoke an unpresented row — so it's a permanent silent strand (status shows `tunnel_down` forever). Compounded by B1 (`proxy off;on` won't free the row, so `existing!=nil` persists). Defeats C5's HA goal for that node.
- **Fix direction:** Give the cluster path a re-mint trigger when an existing row is non-functional: in `reconcileProxySession`, if the row exists but the node has been `!proxy_ready` (i.e. never bound) for a dwell window AND the agent did not re-present a matching token hash on register, ROTATE (free + re-allocate a fresh port/token under `applyMu` per B2's fix) — mirroring the single-mode `enableProxy` keep-vs-replace at `proxy.go:103-117` and `proxyDirectiveForRegister`'s mint-on-mismatch. The register path can detect the mismatch via `req.LocalPorts[__proxy__].TokenHash` like single mode already does.

### M4 — Proxy Home-rehome calls `ApplyHome` with no `HasSession`/`openHomeFromState` recovery; a rehome with the tunnel session absent silently no-ops yet advances `homeEpoch`, stranding the proxy *(C5-DP-05)*
- **Where:** `internal/agent/proxy.go:125-135` (C5 Home branch); `tunnel/tunnel.go:937-944` (`ApplyHome` returns nil no-op when the session is absent); contrast the D6-fixed expose path (`tunnel_adapter.go:98-110`, `agent.go` `openHomeFromState`).
- **Scenario:** The rehome branch guards only on `p.srv != nil` and calls `ha.ApplyHome(p.publicPort, …)`. But the tunnel session is independent of the SS server: `Client.ApplyHome` returns `nil` (success no-op) when `c.sessions[publicPort]` is absent. A proxy tunnel session can be absent while `p.srv!=nil` — e.g. a terminal DENY on a superseded epoch (`tunnelTokenLookup`) called `dropSession`, or a boot-order race; nothing nils `p.srv`. On that no-op the agent treats `err==nil` as success: advances `p.homeAddr`/`p.homeEpoch`, persists, logs "proxy rehomed" — with NO tunnel opened. The monotone guard `d.Home.Epoch > p.homeEpoch` then blocks a same-epoch re-fire, and even a higher-epoch rehome re-no-ops (session still absent). Because cluster mode never re-mints a token (M3) and `openHomeFromState` scans only `sf.PortTokens` (the proxy footprint lives in the separate `StateFile.Proxy` slot), nothing recovers it — manual `proxy off/on` only. This is precisely the divergence the expose path fixed for D6; the proxy rehome path does not use the `homeSessionChecker`/`openHomeFromState` recovery.
- **Fix direction:** Before treating `ApplyHome`==nil as success, assert the session actually exists (`HasSession(publicPort)`); on absence, re-open the proxy tunnel from state (an `openHomeFromState`-style path that includes the `__proxy__`/`StateFile.Proxy` footprint), OR do **not** advance `p.homeEpoch` on a no-op so a subsequent reaper re-push retries. Reuse the D6 `homeSessionChecker` adapter the expose path already has.

### N0 — Typed degraded write-refusal (`FROZEN_READONLY`/`DISABLED_NO_QUORUM`) is unreachable for proxy control writes; no-quorum ctl gets a bare timeout *(C5-FCD-2 — CONFIRMED real, severity corrected BLOCKER→MINOR)*

Don't leave both the dead code and the contradictory comment.

### N1 — Cross-allocation stale rehome can fence the authoritative home forever *(TWO-EPOCH-2, unverified)*
`agent/proxy.go:125-135` applies `ApplyHome(p.publicPort, …)` using the current runtime port and a runtime-global monotone guard `d.Home.Epoch > p.homeEpoch`, but the home epoch is per-allocation (`PlanAllocateProxy` bakes epoch 0 for each fresh `__proxy__` row). Across an allocation boundary (off→on / free→re-allocate at home epoch 0), a stale rehome directive minted for the prior allocation (home epoch >0) that arrives after the rebuild can pass `>0 > 0`, re-dial the new port to the old home, and poison `p.homeEpoch` above the new baseline — fencing the authoritative epoch-0 home forever. Reachable only under cross-publisher reordering across a leadership change. **Fix direction:** scope the home-epoch guard by `d.Home.PublicPort` (ignore a directive whose `PublicPort` ≠ the current allocation), so the per-allocation epoch reset isn't mistaken for a stale lower home.

### N2 — Failed `ApplyHome` during rehome still re-ACKs ready → `/sub` briefly advertises a home with no agent tunnel *(TWO-EPOCH-3, unverified)*
`rehomeProxy` commits `OpPortReassignHome` (home→B) *before* pushing the directive (`proxy_reconcile.go:122-131`), so `/sub` renders B's host immediately. In `applyProxyDirective` the rehome branch advances `p.homeEpoch` only on `ApplyHome` success; on a transient failure (`home_catching_up`/`ErrHomePinsRequired`) it only logs a Warn and does NOT propagate the transient — control then falls through to the exact-equal keyset re-ACK (`proxy.go:143`) which `pubProxyReady(true)`. So `proxy_ready=1` keeps the node in `/sub` while `/sub` points at home B which has no tunnel session yet — a brief black hole until the reaper's next tick. **Fix direction:** on a transient `ApplyHome` failure in the rehome branch, publish unready (or return without the exact-equal re-ACK) until `ApplyHome` succeeds, mirroring `applyOneHome`'s `home_catching_up` surfacing.

### N3 — `proxy status --cluster` reports the ANSWERING broker's public host, not the node's HOME host *(C5-DP-06, unverified — confirmed in code)*
`proxyStatusNodesCluster` (`proxy.go:414`) sets `e.PublicHost = b.publicHostFor()` (whichever broker answered the RPC) when `proxyHomeHealthy`, but `/sub` actually serves each node from its HOME broker's `cluster_nodes.public_host` (`subhttp.go:195,251`). So status shows a host that doesn't match where `/sub` points subscribers, defeating the cluster-view's purpose. `e.HomeBroker` carries the node_id but `PublicHost` is wrong. **Fix direction:** project the home node's `public_host` (`clusternodes.LookupByNodeID(alloc.HomeBroker).PublicHost`), not the local broker's.

### N4 — Render-equivalence gap: `/sub` gates on `public_host!=''` while reaper/status gate on `cert_fp!=''` *(C5-DP-07, unverified — confirmed in code)*
`/sub` (`subhttp.go:204-205`) gates home on `cn.phase='VOTER' AND cn.public_host != ''`; `proxyHomeHealthy` (`proxy_reconcile.go:93`) and `pickProxyRehomeTarget` (`proxy_reconcile.go:138`) gate on `Eligible() AND cert_fp != ''`. Different columns. A VOTER with `cert_fp` set but `public_host` empty is judged healthy (never rehomed) and shown ready by status, yet permanently EXCLUDED from `/sub` → silently un-vendable forever; the inverse renders in `/sub` while status/reaper call it unhealthy. **Fix direction:** make both predicates test the same VOTER-home-deliverable condition (`cert_fp != '' AND public_host != ''`), so status ⟺ `/sub` render-equivalence holds and a non-deliverable home triggers a rehome. (Folds naturally into M1's fix.)

## Suggested new tests

`test/c5/` does not exist — the plan's entire named gated suite is missing. Create it (`//go:build c5_integration`, `TestC5Matrix -race`, kept out of `make test`) plus pure unit tests in `make test`. Minimum set tied to the findings above:

1. **`TestC5ProxyOffTearsDownDataPlane`** (B1, gated): cluster, proxy on, mint a subscriber, drive an agent to `proxy_ready=1` with a live SS exit reachable through the home's public port; issue `proxy off`; assert (a) a TCP dial to the home public port is refused, (b) the `__proxy__` `port_allocations` row is FREED (out of ALLOCATED), (c) the agent received `Enabled:false` and `proxyBound()==false`, (d) any existing subscriber connection is severed within a bounded time. All four fail today.
2. **`TestC5ProxyAllocateNoFailStopUnderConcurrentExpose`** (B2, gated): proxy on (reaper allocates `__proxy__`) while a concurrent loop fires `expose` allocations on the SAME leader from the same `[low,high]` band; assert no node panics / no FSM fail-stop and no two ALLOCATED rows share a port. Plus a focused determinism test: after `PlanAllocateProxy` returns its baked cmd, INSERT a competing ALLOCATED row on the baked port, Apply the proxy cmd, assert it does NOT fail-stop (proving the port must be chosen under `applyMu`).
3. **`TestC5KillHomeRehome`** (M1, gated): 3 brokers, proxy home pinned to VOTER B, agent serving; hard-kill B *without* drain/retire (leave `phase='VOTER'`); advance the reaper past `proxyRehomeDwell`; assert `OpPortReassignHome` fires, the `__proxy__` home moves to a live VOTER, and `/sub` renders the new home. No rehome occurs today.
4. **`TestC5TunnelDownNotResurrectedByHeartbeat`** (M2, gated): bound agent; kill ONLY the reverse tunnel (keep SS server + NATS up); assert after one heartbeat interval the node is NOT in `/sub` and `proxy status --cluster` reports `tunnel_down`. Today `proxy_ready` bounces back to 1 each heartbeat.
5. **`TestC5LostTokenPushReMints`** (M3, gated): proxy on, let the reaper commit the `__proxy__` row, then DROP the token-bearing forwarded push (or wipe the agent `state.json`) and re-register; assert the agent eventually binds (usable token+port) within a bounded time rather than parking on "awaiting full directive".
6. **`TestC5RehomeAbsentSessionNoFalseRehomed`** (M4, unit, `internal/agent`): with a fake home adapter whose proxy tunnel session is absent (`HasSession==false`), deliver a newer-`Home.Epoch` rehome while `p.srv!=nil`; assert the agent re-opens from state OR does NOT advance `p.homeEpoch` on the no-op (so a later re-push retries) — not a false "rehomed".
7. **`TestC5NoQuorumWriteRefused`** (N0, gated): 3 brokers, partition the ctl onto a minority; send `proxy.set`/`proxy.sub.revoke`; assert a typed `proxy_frozen_readonly` (freeze) / `proxy_disabled_no_quorum` (disable) reply rather than a request timeout. Plus a unit test that `proxyWriteRefused` can return true on some reachable path (or, if the plan is amended to broadcast+leader-only, a test asserting the dead verbs/branches are removed).
8. **`TestTwoEpochCrossAllocationStaleRehome`** (N1, unit): establish proxy on P1/home A/epoch H>0; off/on to a fresh allocation P2/home B/epoch 0; deliver a stale `Home{PublicPort:P1, epoch:H}` after the rebuild; assert it is scoped out by PublicPort mismatch and the agent stays on B (`p.homeEpoch` stays 0).
9. **`TestProxyRehomeApplyHomeTransientNoFalseReady`** (N2, unit): script `ApplyHome` to return `home_catching_up` on the first rehome; assert the agent does NOT publish ready until a later re-push succeeds.
10. **`TestProxyStatusClusterHomeHost`** (N3, unit/gated): 2-broker cluster, agent homed on B; call `proxy status --cluster` against A; assert the row's `PublicHost` equals B's `public_host` (matching `/sub`), not A's.
11. **`TestSubRenderEquivalence`** (N4, unit): construct a VOTER home with `cert_fp` set but `public_host=''` (and the inverse); assert `proxy status --cluster` readiness and the `/sub` render AGREE (both vend or both exclude), and a non-deliverable home triggers a rehome.

Plus the plan's remaining named drills not yet written: `SubCreateAtFollowerReturnsURL`, `RehomeFlapHysteresis`, `RehomeCASSingleWinner`, `FrozenVsDisabled`, `KeysetRotateUnderPartition`, `SecretBoundary`, `ForceHomeGate`, `GuardNoDirectProxyWrite`, `SingleModeByteEquiv`, and the pure `TestProxyClusterState`/`TestProxyReadyReason`/`TestDecideProxyEvents`/`TestSubVendGate`/`TestTwoEpochSeparation`.
