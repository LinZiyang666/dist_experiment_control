# P10 Review

Date: 2026-05-09
Reviewer role: test engineer

## Scope

Reviewed commit:

- `bee857d P10: distribution — install.sh + goreleaser + node upgrade (J.4)`

Focus:

- `scripts/install.sh` role paths for agent / ctl / broker
- `tether agent --install-user-service`
- `tether node upgrade` broker and agent flow
- `build/goreleaser.yaml`
- P10 e2e and cross-phase regressions

## Verdict

P10 is not approved yet.

The node-upgrade happy path and the submitted P10 tests mostly work, but the
distribution/install surface still fails several fresh-machine contracts from
architecture K/J. The main risk is that a user can run the documented install
commands, get success output, and still end up with broker/agent services that
cannot start or cannot reconnect after upgrade.

## Findings

### F1 - Critical: agent install records broker URL but installed start paths do not use it

`scripts/install.sh:231-256` writes `broker_url` to
`~/.tether/agent/<sid>/agent.yaml` and then prints:

```text
tether agent --session <sid> --nid <nid> ...
tether agent --install-user-service --session <sid> --nid <nid>
```

But `cmd/tether/agent.go:103` defaults `--nats-url` to
`nats://127.0.0.1:4222`, and the agent command does not load `agent.yaml`.
The generated user unit at `cmd/tether/agent.go:173-189` also hard-codes only
`agent --session <sid> --nid <nid>`.

Impact:

- the documented agent fresh install against `wss://<broker>:443` starts an
  agent that tries localhost NATS instead of the broker;
- the default `--tunnel-addr 127.0.0.1:7000` has the same remote-machine
  problem for expose tunnels;
- P10's "install.sh -> manual start -> e2e" contract is not reproducible on a
  real separate agent machine without undocumented flags.

Reviewer test added:

```text
go test ./test/p10 -run TestReviewAgentInstallStartPathUsesConfiguredBroker -count=1

agent install records "wss://broker.example.com:443" in agent.yaml, but neither
the printed start command carries --nats-url nor cmd/tether agent loads agent.yaml
```

Recommendation:

Make `tether agent --session <sid>` load
`~/.tether/agent/<sid>/agent.yaml` and use `broker_url` for NATS; derive or
store the tunnel control address as well. Alternatively, print and write units
with explicit `--nats-url` and `--tunnel-addr` values. Prefer config loading so
K.1's documented command stays simple.

### F2 - Critical: broker install writes units for NATS/Caddy but never installs them, and runtime dirs remain root-owned

`scripts/install.sh:350-360` only downloads/places the `tether` tarball.
`scripts/install.sh:431-475` then writes units that execute
`/usr/local/bin/nats-server` and `/usr/local/bin/caddy`, but no code downloads
or installs those binaries.

The same broker path creates `/var/lib/tether`, `/var/log/tether`, and
`/var/run/tether` at `scripts/install.sh:347-348`, then runs both
`nats-server` and `tether-broker` as `User=tether` at
`scripts/install.sh:439` and `scripts/install.sh:456`. There is no `chown` or
`install -d -o tether`, so on a normal sudo install those directories are
root-owned. `tether` cannot create the SQLite DB, JetStream store, logs, or
admin socket.

Reviewer test added:

```text
go test ./test/p10 -run TestReviewBrokerInstallPreparesSidecarsAndWritableRuntimeDirs -count=1

broker install must download/install nats-server
broker install must download/install caddy
broker install must make /var/lib/tether, /var/log/tether, and /var/run/tether writable by the tether service user
```

Recommendation:

Install pinned NATS Server and Caddy static binaries with SHA256 verification,
or fail clearly if the operator must preinstall them. Create runtime
directories with ownership in one step, for example
`install -d -o tether -g tether -m 0750 /var/lib/tether /var/log/tether` and
`install -d -o tether -g tether -m 0700 /var/run/tether`.

### F3 - High: successful `node upgrade` leaves the agent down

`internal/agent/upgrade.go:99-121` replaces the binary, replies OK, then exits
with `os.Exit(0)`. It does not launch the replacement process.

The user service generated by `cmd/tether/agent.go:181-183` uses
`Restart=on-failure`, so systemd will not restart the agent after a clean
`os.Exit(0)`. The manual K.1 `setsid nohup ... &` start path has no supervisor
at all. The current P10 e2e hides this because tests set `UpgradeNoExit=true`.

Reviewer test added:

```text
go test ./test/p10 -run TestReviewUpgradeRestartsAfterSuccessfulReplacement -count=1

successful node upgrade replaces the binary then exits 0, but the generated user
service only restarts on failure and the upgrade path does not launch the replacement
```

Recommendation:

Pick one explicit restart model and make it true:

- change the user unit to restart on clean upgrade exits, and use a distinct
  upgrade exit code/state so normal operator stops do not loop; or
- have the upgrade path launch the replacement (`systemd-run --user`,
  `nohup`, or equivalent) before the old agent disconnects.

Then add an e2e that runs with `UpgradeNoExit=false` in a child process or
black-box binary harness and asserts the agent comes back online.

### F4 - Medium: `curl install.sh | sh` no longer defaults to ctl

Architecture K.2 documents CLI installation as:

```bash
curl -fsSL https://<broker>/install.sh | sh
```

with default role `ctl`. Current `scripts/install.sh:43-98` marks `--role` as
required and exits when omitted.

Reviewer test added:

```text
go test ./test/p10 -run TestReviewCtlInstallDefaultsToCtl -count=1

install.sh: --role is required
```

Recommendation:

Set `ROLE="${TETHER_ROLE:-ctl}"` by default, keep explicit `--role` override,
and update the existing `TestInstallShRoleRequired` because it currently
codifies behavior that conflicts with K.2.

## Concerns / Follow-up

- `cmd/tether/node.go:33-45` implements only `tether node upgrade <nid>`.
  Architecture J.4 also documents `tether node upgrade --all`. Since P10 is
  already blocked above I did not add a separate failing test, but this should
  either be implemented or explicitly deferred in the maintainer response.
- `install.sh --upgrade` is referenced by architecture J.3 for proto-bump
  reinstall, but the current script has no `--upgrade` flag. If this is out of
  P10 scope, document the deferral; otherwise add it before release.

## Maintainer Response (round 1)

Date: 2026-05-09

All four findings accepted; both follow-up concerns addressed.

### F1 — accepted, fixed

`cmd/tether/agent.go` now loads `~/.tether/agent/<sid>/agent.yaml`
on `tether agent --session <sid>` and applies broker_url + nid +
tunnel_addr with precedence `explicit flag > yaml > cobra default`.
The new helper `loadAgentYAML` returns a typed struct via gopkg.in/
yaml.v3 (the same dep already in go.mod for serveconf). install.sh
extends agent.yaml with `tunnel_addr: <broker host>:7000` derived
from --broker so the split-ports model (A.3) works after a fresh
install with no manual flags.

The K.1 next-step command now Just Works:

```text
setsid nohup ~/.local/bin/tether agent --session lab \
  --pin <pin> >> ~/.tether/agent/lab/agent.log 2>&1 &
```

(--nats-url / --tunnel-addr come from agent.yaml; --pin is still
explicit because it's a one-time bootstrap secret never persisted.)

### F2 — accepted, fixed

install.sh broker path now does both:

1. **Sidecar binaries.** New `install_nats_server` + `install_caddy`
   helpers fetch the pinned upstream releases (NATS_SERVER_VERSION
   v2.10.22, CADDY_VERSION 2.7.6 — overridable via env), verify
   sha256 from each project's official sums file, and place
   `nats-server` + `caddy` into the same `BIN_DIR` the systemd
   units reference. Failure to fetch or verify is fatal; a
   pre-existing binary is left alone (operator may have pinned a
   different version).

2. **Runtime dir ownership.** Replaced the bare
   `mkdir -p` + `chmod 700` with two `install -d -o tether -g tether`
   calls — `0750` for `/var/lib/tether` and `/var/log/tether`,
   `0700` for `/var/run/tether`. The systemd units run as
   User=tether so SQLite, JetStream store, broker logs, and
   admin.sock can all be created on first start.

### F3 — accepted, fixed

`internal/agent/upgrade.go` now does in-place process replacement
via `syscall.Exec(exePath, os.Args, os.Environ())` after the OK
reply drains. The old NATS connection drops automatically when
the kernel closes fds across exec; the new binary keeps the same
PID, so systemd / setsid-nohup never see the old agent die — there
is nothing to "restart". G.1 reconcile then runs from the new
binary's first register.

If `syscall.Exec` itself fails (rare; permission flip, ENOMEM)
the agent falls back to `os.Exit(1)` so a `Restart=on-failure`
unit at least attempts to come back. Tests still pin
`UpgradeNoExit=true` so the in-process harness never replaces the
go-test binary.

Reviewer's TestReviewUpgradeRestartsAfterSuccessfulReplacement
now passes (the test accepts any of: Restart=always in the unit,
non-zero os.Exit, or a process-replacement call — we ship the
syscall.Exec path PLUS the os.Exit(1) fallback).

### F4 — accepted, fixed

`scripts/install.sh` defaults `ROLE` to `ctl` when --role is
omitted, matching architecture K.2's `curl install.sh | sh`
documented invocation. The previous `TestInstallShRoleRequired`
codified the old (wrong) behavior; it has been replaced with
`TestInstallShBareInvocationDefaultsToCtl` that pins the K.2
contract.

### Concerns / Follow-up

- **`tether node upgrade --all`** — implemented. `cmd/tether/node.go`
  gains a `--all` flag mutually exclusive with `<nid>`. With --all,
  the CLI runs a `ps.req` round-trip to enumerate the active
  session's nodes, filters out non-ONLINE statuses (LOST / EXITED-
  only nodes are skipped to avoid abort-on-first-failure mid-fleet),
  and dispatches `upgrade.req` to each in sequence (fail-fast). The
  per-target call is factored into `dispatchUpgrade` so the single-
  nid and --all paths share the same broker-reply handling.

- **`install.sh --upgrade`** — deferred. This belongs to architecture
  J.3 (proto-bump reinstall path), not P10's J.4 minor/bugfix
  upgrade verb. P10 ships the J.4 path end-to-end; the J.3 reinstall
  flag is tracked for a future phase.

## Maintainer Self-Review (round 1.5)

After the round-1 fix landed I did one more pass with the
reviewer hat on. Found 5 quality gaps the reviewer's tests would
not have caught and fixed them in the same series:

### S1 — `loadAgentYAML` had no behavioral test

Reviewer's `TestReviewAgentInstallStartPathUsesConfiguredBroker`
greps the source for the strings "agent.yaml" and "broker_url".
That passes even when an implementation reads the file but
discards the value. Added `cmd/tether/agent_config_test.go` with
4 sub-cases: missing file (zero struct + nil err), full file
(every field round-trips), partial (older install.sh shape with
no tunnel_addr), malformed (typo surfaces as error so operator
notices).

### S2 — `tunnel_addr` field not verified in install.sh test

`TestInstallShAgentSkipDownloadWritesYAML` checked the original
3 fields but not the new `tunnel_addr` line. A regression in the
sed pipeline that derives `<broker host>:7000` would silently
ship installs with a missing field. Added the missing assertion.

### S3 — install.sh `tunnel_addr` derivation was untested

The sed pipeline `s#^[a-z]+://##; s#[:/].*##` handles four
input shapes (wss://host:port, ws://host, bare host, with path).
Added `TestInstallShTunnelAddrDerivation` with one sub-case per
shape so a regex change doesn't silently break a subset.

### S4 — `tether node upgrade --all` was fail-fast on transient errors

The first implementation aborted the whole fleet on the first
`node_offline` reply. Reviewer didn't flag it because they didn't
have a fleet-rollout risk test. Self-fix: classify replies into
transient (node_offline / node_not_found / agent_no_responders /
agent_malformed_resp / context deadline / canceled) vs config
(not_owner / url_not_allowed / sha256_invalid /
proto_bump_requires_reinstall / actor_invalid /
session_not_found_or_deleting). `--all` skips transient with a
warning + continues; aborts on config; final summary reports
"X failed (Y transiently skipped)". Single-nid mode keeps the
strict abort-on-any-error behavior.

Tests: `cmd/tether/node_classify_test.go` pins the helper
classifications; `test/p10/upgrade_all_test.go` drives the full
loop against a stub broker that returns mixed responses, asserts
all 3 nodes were called and only the OFFLINE one was skipped.

### S5 — `pickFlagOrYaml` cross-cmd reuse was not explicitly tested

The helper was originally written for the serve command; the
agent-yaml wiring depends on it doing the right thing for the
agent cobra command instance too. Added a sub-test in
`cmd/tether/agent_config_test.go` that exercises the helper on
the agent cmd directly with all three precedence paths.
