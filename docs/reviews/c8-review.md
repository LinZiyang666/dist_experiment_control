## Confirmed MAJORs

### M1 — `join prepare --self-id` is a non-existent flag, emitted by the apply-plan engine, the live recovery wizard, and the same-PR runbook/usage rewrite
The flagship C8 replacement for `add`/`sign-join` defines its joiner-id flag as **`--node-id`** (`cmd/tether/cluster_join.go:96`); there is no `--self-id` on `join prepare` or any parent. Yet every operator-facing rendering of it instructs `--self-id`:
- `internal/clusterspec/spec.go:110` — the `cluster apply`/`doctor` reconcile-plan **machine-generates** `tether cluster join prepare --self-id %s …` as the Order=0 step for any desired-voter-not-in-cluster. `Diff`'s own contract (spec.go:83-84) is "every step is a printed verb the operator runs."
- `cmd/tether/cluster_offline_wizard.go:73` — `recoverGuided` step 3 prints the same, reachable via `cluster recovery rejoin prepare --guided` and the hidden `cluster recover --guided` alias.
- `docs/cluster-runbook.md:15,54,203,266` and `docs/usage.md:750` — the same-PR rewrite; `docs/usage.md:865` documents `--self-id (必填)` as the flag's *name* in the reference table.

Proof (built binary): `tether cluster join prepare --self-id brk-b --raft-addr x:7400 --nats-route nats://x:6222 --tunnel-addr x:7000` → `error: unknown flag: --self-id` (exit 70); the same line with `--node-id` parses and emits a valid `tether-join:v1:` bundle.

Discipline violated: rubric "spec.go prints a verb that does not exist" / "a runbook command that does not exist." Rule 4 (bootstrap) is NOT broken — the mechanism works via `--node-id` (C8 tests `cluster_c8_test.go:181,242` use it correctly) — so this is MAJOR, not BLOCKER. Root cause: the sibling recovery/offline verbs (`recover`/`force-single`/`diagnose`/`init`) legitimately take `--self-id` (`cluster_offline.go:67,123`, `cluster_recovery.go`, `cluster.go:700`), and the token leaked into `join prepare`.

Fix direction: `--self-id` → `--node-id` at `spec.go:110`, `cluster_offline_wizard.go:73`, `docs/cluster-runbook.md:15,54,203,266`, `docs/usage.md:750` and the `:865` flag-reference row. (Do NOT touch the `recovery rejoin prepare --self-id` lines at runbook:22,189,349 / usage:757 / wizard line-4 — those are valid.)
