# e2e 并行化 — 增量说明（提交外审）

> **范围外声明**：本增量**不在** `batch-a-plan.md` 内，也不在批次 A 外审的验收范围内。
> 它是批次 A 外审结束后新提的需求，按"post-1.0 叶子增量"独立立项、独立外审。
> 之所以不并进批次 A：会把外审 diff 从"可逐条读"变成"翻不完"，淹没真正需要人看的部分
> （退出码分类、ACL 删授权、fence 收口、retire 删除）。理由与当初拒绝把 `docs/reviews/` 归档
> 塞进批次 A 完全一样。

## 1. 缘起与范围

**缘起**：`make e2e` 串行 18m21s。开发机是 2 socket × 22 物理核 = 44 核 / 88 线程，
而整轮串行期间 **CPU 97.5% 空闲、磁盘 0% util、196 GB 内存空闲**——闸门在一台几乎全闲的机器上跑了 18 分钟。

**范围**：
- 新增 `test/e2e/parallel/`（5 个文件，`package main`，不进 `go test`）
- 新增 `make e2e-parallel` 目标
- 注释订正：`Makefile`、`test/e2e/all_phases_test.go`、`CLAUDE.md` §5
- **不碰任何产品代码**，`make e2e` 的命令行一字未改

## 2. 被推翻的旧结论（这是本增量的前提）

`Makefile` 与 `all_phases_test.go` 原先都写着：并行化"试过、测过、已回退"，因为 D8 在 2-way、
D5 在 4-way 就 flake（"routed JS server not ready"）。

**flake 是真的，归因是错的。** 不是资源饿死（机器 97.5% 空闲），而是**缺 CPU affinity**：
`GOMAXPROCS` 只限制线程数、不限制线程跑在**哪**，两个测试进程仍会跨 socket 交错，
而本机跨 NUMA 访问是本地的 **2.1 倍**（distance 21 vs 10）。带硬 deadline 的 raft/JS 握手正好吃这个亏。

绑核之后，被点名"不能容忍 2-way"的 D8 与"不能容忍 4-way"的 D5 全绿。

> 这与 simcluster 那次"drills 须串行"是同一形态——那次的真因是
> `fs.inotify.max_user_instances` 耗尽，也与 CPU/内存/IO 无关。
> **两次都是把调度问题误诊为供给问题。**

## 3. 设计

| 文件 | 职责 |
|---|---|
| `topology.go` | 运行时探测：`Cpus_allowed_list`（**不是**所有 CPU）、`thread_siblings_list`、NUMA 节点；`runningHeavyCPUs()` 排除"此刻有大进程驻留"的核（**不是**利用率测量，见 §10 限制 6） |
| `alloc.go` | 三条性质：单元间不共享 CPU、单元不跨 NUMA 节点、只分配**整物理核**（不把 SMT 兄弟拆给两个单元） |
| `main.go` | `go test -list` 动态发现、work-stealing 队列、`numactl --cpunodebind/--membind/--physcpubind` + `GOMAXPROCS` |
| `split.go` | AST 解析 `all_phases_test.go`，抽取每个矩阵的 `(tags, packages, timeout)` |
| `shard.go` | 对主导包按**测试名**分片，round-robin 分配 |

**绑核是动态的**：按当轮并行度现算分配，不存在"某测试永久绑 5 号核"。
worker 按**节点容量**分配（外审 M1：原先平均分，不均衡拓扑下会向 1 核节点要 2 个 worker 而失败）。

## 4. ⚠ 静默少跑/语义漂移缺陷（共四处，外审重点）

> 本节最初只记录第 1 处（主进程自查发现）。外审又查出三处**同类**缺陷，
> 一并列出——四处全部是"解析层出错 → 跑得又快又绿又不对"，这不是巧合，
> 而是这套设计的固有风险面（见 §10 限制 2）。
>
> | # | 缺陷 | 发现者 | 后果 |
> |---|---|---|---|
> | 1 | run-whole fallback 按名字过滤，丢 `TestAllPhases` | 主进程自查 | 漏跑 11 个 phase 套件 |
> | 2 | `found` 是函数级 bool，混合命令形态只跑可解析的一半 | 外审 B2 | 静默漏 command |
> | 3 | 丢失原始 `-run`，跑成整包 | 外审 B3 | **跑的不是同一个矩阵** |
> | 4 | 非 split 默认模式把成功判为失败 | 外审 B4 | 防御措施自身成为缺陷 |
>
> 第 3 处最严重：它不是少跑而是跑了别的东西，且 §5 的覆盖自检**结构上抓不到**
> （数量对、语义漂移）。这直接导致新增 identity multiset 对账（外审 M4）。

### 4.1 第 1 处的完整经过

**在验证"分片是否漏测"时，它自己暴露了一个严重缺陷。**

`split.go` 的 run-whole fallback 条件曾是：

```go
if !found && strings.HasSuffix(name, "Matrix") {
```

`TestAllPhases` 不以 `Matrix` 结尾，而它的 `exec.Command` 在 `runPhase()` 这个**另一个函数**里、
不在自己的 body 内，所以 `found == false`。两个条件一夹，**它被静默丢弃**。

**后果：并行版从来没有跑过 p1–p10、p13 共 11 个 phase 套件。**
在此之前上报的 "2m22s / 7.9× / 30/30 ALL PASS" 全部作废——那是**漏跑三分之一闸门**跑出来的数字。
每一轮都又快又绿，且没有任何一处报错。

**修复**：fallback 不再按名字过滤——没解析出 unit 就整体跑，对所有顶层测试一视同仁。

**这个缺陷不是被测试跑绿抓到的，是被为回答"覆盖是否等价"而临时补的自检抓到的。**
所以自检留了下来，并加了第二道。

## 5. 两道自检（针对"少跑还报绿"这一类）

| 自检 | 时机 | 断言 |
|---|---|---|
| 覆盖自检 | 启动前 | 串行矩阵里的**每个顶层测试**都必须有对应 unit，否则 `fatal` 拒绝启动 |
| 身份对账 | 每轮结束 | 调度项与结果按 **multiset 比较 identity**（缺失 / 多余 / 重复都报），否则判 FAIL |

两者针对同一种失败形态：**少跑的一轮和快的一轮长得一模一样**，损失天然是静默的。

第二道原为**数量**比较，外审两次点名：B4——它读了 `len(units)`，而默认非 split 模式的 work 在
`tests` 里、`units` 恒空，于是每次成功的默认运行都判失败（**防御措施自身成了缺陷**，且因为
Makefile 总传 `-split` 而从未被暴露）；M4——数量相等不等于集合相等，B3 就是"数量 107 完全正确、
命令语义已漂移"的实例。现已改为 identity multiset。

**覆盖自检只在全量模式生效。** `-run` 下操作者是**故意**要子集，此时强制全覆盖会让自检
本身成为"禁止按需跑"的东西。该轮会打印 `PARTIAL RUN (-run ...)`，使子集结果不会被误当成闸门。
区别在于：自检抓的是**意外丢失的覆盖**，而非**有意声明的取舍**。

## 6. 测量

| 配置 | 时间 | 说明 |
|---|---|---|
| 串行 `make e2e` | **18m21s** (1101.166s) | 15/15 矩阵 PASS |
| 并行 `make e2e-parallel` | ~3m23s | **数字已作废，见下** |

**并行侧的加速比目前没有可引用的数字。** 依次作废的原因：

1. 最早的 **2m22s / 7.9×** ——漏跑 `TestAllPhases` 连带 11 个 phase 套件（§4 第 1 处）；
2. 随后的 **3m23s / 5.4×** ——B3 未修，`TestTransferDefaultsMatrix` 与 `TestPhaseFluidityMatrix`
   跑的是**整包而非矩阵声明的子集**，即"跑的不是同一个矩阵"（§4 第 3 处）。

B2/B3/B4 修复后**未重新测速**，且因为满载 flake 未解决（§10 限制 1），
现阶段测出的数字也不构成"可替代串行"的论据。**在这些前提改变之前不引用任何加速比。**

### 最终外审后的有效测量

最终外审又把动态 timeout、未知 flag、非 `go test` argv 和本地 helper 中的命令改成
**整矩阵 fail-closed fallback**，并把默认 worker 从 Makefile 的固定 20 改为按拓扑自动选择
（本机仍取 20 个原始 slice，小型 CI 不再在测试开始前拒跑）。在这份最终代码上：

| 配置 | 结果 |
|---|---|
| 单轮 | **2m53.609s / 99 units / 15/15 / ALL PASS** |
| 连续两轮 | **5m23.398s / 198 units / ALL PASS** |
| 合计 | **三轮 297 units / 0 failure** |

相对 18m21s 串行基线，取最慢的 2m54s 约为 **6.4×**。此前两组作废数字仍保留在上文，
不可与这组最终证据混用。

**一条被实测推翻的直觉**：按**包**拆并行反而更慢（5m11s vs 4m48s）。
`go test ./a/... ./b/...` 本来就并行跑各包，自己拆等于重做工具链的活还多付进程开销。
真瓶颈在**包内**：Go 只在包间并行，包内除非测试自调 `t.Parallel()` 否则串行——
`internal/broker` 一个包 496 个测试串行 4m32s，**只用 0.7 核**（其余是等待，不是算）。
按测试名分片（每片独立进程，比加 `t.Parallel()` 安全：不共享内存、全局状态仍 per-process）
才把该包天花板从 4m37s 砸到 58s。**优化前先量瓶颈在哪一层。**

分片正确性已实测：shard 1 声明 62 个测试、实际执行 62 个，8 × 62 = 496 = 全集。
（中途一次 `COVERAGE MISMATCH` 是验证方法错误——`go test -list` **忽略** `-run`，
不能用 `-list` 验证 `-run` 的过滤效果。）

## 7. 副产物：逼出一个隐藏的 harness 缺陷

并行化把 `test/d7` 的一个缺陷逼了出来：它用 **60ms** 的 raft 心跳超时，
而该套件按 §5 必须带 `-race`（内存访问慢 5–10 倍），一次 GC 暂停就足以在 `AddNode` 提交途中掀翻 leader。

先调到 300ms（d7 从约 1/7 失败变成串行 6/6、并行两轮 30/30 全绿），
批次 A 外审 M4 进一步指出 300ms 仍只有生产 `MultinodeHeartbeatTimeout` 的三分之一——
是"调到 `-race` 刚好能过"而不是"对齐生产"，故最终对齐到 **1000ms**。运行时长不变
（该超时约束的是故障检测，不是 happy path）。

**教训**：写测试超时要按它**实际运行的环境**写（`-race` + 满负载），不是按理想环境。

> 该 d7 改动属于批次 A（外审 M4），不在本增量内，此处仅记录因果。

## 8. 权威度（**最终裁定：并行是唯一闸门**）

**`make e2e-parallel` 全绿即通过。严禁全量跑 `make e2e`，也严禁并行过了再串行"复核一遍"。**

理由不是速度，是**有效性**：全量串行做了多年闸门，四类真实缺陷**一个都没抓到**——
17 处比生产短 7–20 倍的 raft 计时、d3 与 d7 两处身份竞态、端口 TOCTOU，
**全部由并行满载压出来**（见 `parallel-flake-rootcause.md`）。
并行版另有两道串行版根本没有的自检：顶层测试无对应单元即拒跑、调度项与结果 multiset 不符即判 FAIL。
一个十八分钟、抓不到东西、却让人以为已经验过的闸门，是仪式不是保险。

**串行唯一合法用途**：并行报错后单独跑那一个测试定位（`go test ./test/pX/...`、
`-tags dN_integration -race ./test/dN/`、`-run TestXxx`），**定位完即止，不得升级成全量**。

**决策沿革（如实记录）**：主进程最初建议串行留作发版闸门；用户指示提到同权威；
外审用满载三处 flake 推翻并要求恢复串行权威；那三处根因随后全部查清修复
（四类根因、开发者三轮 300 单元零失败；最终外审严格 fallback 配置另跑 297 单元零失败），
**外审结论所依赖的事实已不成立**；
用户据此最终裁定并行为唯一闸门。**每一步的依据都是当时可得的证据。**

## 10. 已知限制 / 未做（登记，不掩盖）

1. ~~**满载下三处原有 flake**~~ —— 已根因修复；最终外审三轮 297 units 未复现 D3 follower
   PIN、broker mutating redirect 或 D7 `FollowerStatusViewSource`。
2. **自检覆盖的是已知的两种失败形态**（顶层测试无单元、单元无结果）。
   最终外审新增 helper 内命令、动态参数、未知 flag、非 `go test` argv 的 fail-closed 反例，
   但解析层若以新的第五种方式出错，仍可能不被发现。这是相对共享 manifest 的**结构性额外风险**，
   不因本轮 Pass 消失。
3. **绑核依赖 Linux sysfs；`numactl` 缺失时明确降级为不绑核。** 默认 worker 自动按可用
   物理核选择并封顶 20，2/4 核 CI 分别选择 1/2，不再硬编码 20 后启动即失败。
4. **`shardable()` 是硬编码包名白名单**（`internal/broker`、`internal/cluster`、`test/d4`、`test/d5`）。
   新出现的主导包不会自动被分片——只影响速度，不影响覆盖。
5. **~~无单元测试~~ 已解决**：`test/e2e/parallel` 现有 8 个外审反例测试并进 `make test`。
   此前这条被记成"限制"，而真相是覆盖自检把 parallel 包自己的 `_test.go` 当成串行 gate 的
   顶层测试，**使它不可能有测试**（外审 B5）——限制是自己造的，却记成了外部约束。
6. **`runningHeavyCPUs` 不是利用率测量**：单次 `/proc` 采样只能看到"某个占过 CPU 的进程此刻
   驻留在这个核上"。原函数签名带一个从未使用的 `pct` 参数（函数体里写着 `_ = pct`），
   文档却宣称"自动避开负载 >50% 的核"（外审 M2）。已重命名并降级措辞。
7. **共同的结构化 matrix manifest 未做**（外审 M4 建议）：当前实现仍建立在"解析另一个 runner 的
   Go 源码"这一根本脆弱的前提上——§4 那四处缺陷全部源于此。最终外审已把已知未知形态
   fail-closed，但让测试入口与并行 runner 从同一份结构生成命令仍是更可信的长期形态。
